# 09. Стоимость присутствия SDK — slide-07

**Зачем:** различить скачанные bytes, wall time и CPU. Старый бюджет: 3:30.
Полезное исследование для SDK-команды, но второстепенное для текущего обещанного рассказа.

## Что можно говорить, если возник вопрос

«Мы сравнили две сборки: SDK удалён и SDK установлен, но runtime выключен.
В реально загруженном gzip JavaScript получилось 1871 и 8275 байт. В шести локальных парах разница
navigation → adapter-ready оценена как +21.433 ms с exploratory interval [1.450, 44.650].
Это wall time до выбранного маркера; CPU имеет другой источник и интервал, включающий ноль».

«Из этого нельзя получить универсальный процент overhead. Даже выключенная функция может оставлять
код в сборке, поэтому сначала надо определить, что именно сравниваем».

## Доказательство и ограничения

[Полный протокол и все contrasts](../../../docs/research/performance-observability/F_STRIPPED_STUDY.md),
локальная папка `performance-observability/reports/stripped-1794680848671-8f54/`.
Две сборки, шесть alternating run pairs на одном Mac; это не шесть независимых builds и не принятый overhead budget.
Loaded gzip bytes не равны всему emitted output или сетевому трафику с заголовками.

**Решение:** убрать из основного маршрута. Не тратить 3:30 на тонкости наших SDK-измерений,
пока в основной части отсутствуют hydration, RN startup и именованные инструменты.
