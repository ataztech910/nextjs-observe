# 04. Какое событие заканчивает измерение — slide-02

**Зачем:** зритель должен понимать, что именно означают числа следующих двух сцен.
В старом плане выделено 3 минуты; это слишком много для вводной схемы, предлагаем сократить при пересборке.

## Что говорить

«После нажатия есть несколько разных событий. Начался обработчик, закончилась выбранная работа,
React вызвал Profiler callback, браузер показал результат. Эти моменты нельзя подменять друг другом.
Если я измерил до callback React, я ещё не измерил появление пикселей».

«И слово “готово” требует определения. Маркер первого layout effect — наш маркер приложения.
Он сам по себе не доказывает, что любая кнопка уже отвечает».

## Что показывать

На `slide-02` пройти слева направо по цепочке action → handler → JS work → React completion → visible result.
Указать две границы, к которым вернёмся: A — handler → Profiler callback, B — navigation → first layout effect.
Стрелки концептуальные: не складываем пересекающиеся интервалы как части измеренного critical path.

## Что подтверждено и чего нет

Это объясняющая схема, не запись конкретного interaction. Определения взяты из
[A](../../../docs/research/performance-observability/EXPERIMENT_A_GATE.md) и
[B](../../../docs/research/performance-observability/EXPERIMENT_B_GATE.md).
В текущей карточке нет полноценного объяснения обещанного TTI. Не переименовывать readiness в TTI.
Brief требует объяснить legacy TTI и его исключение из Lighthouse; перед финальным английским текстом
проверить актуальный первичный источник из brief. Здесь новый внешний факт не исследовался.

**Решение:** оставить короткую схему; добавить недостающее объяснение TTI при переработке содержания.
