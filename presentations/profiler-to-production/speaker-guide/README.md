## Актуальное вступление: от проблемы к framework

Подачу и сокращения определяет Андрей. Тайминг не используем как причину удалять или объединять
поясняющие слайды. Исторические номера и минуты в старом аудите ниже не задают текущий маршрут.

После фото спикера и GDG Linz идём по [связному послайдовому тексту](framework-metrics.md):

| Карточка | Зачем она здесь |
| --- | --- |
| `performance-question` | Поставить проблему: наблюдение может выглядеть хорошим, пока выбранная задача пользователя ждёт |
| `user-waits` | Восстановленное объяснение: готовность, ответ и плавность — разные ожидания |
| `framework-map` | Восстановленная Web-карта: переводим вопрос в начало, конец и источник измерения |
| `framework-proxies` | Определить, что можно заключить из Lighthouse, bytes и actualDuration |
| `framework-choice` | Собрать общую схему как вывод: пользовательский результат → причина → решение |

[Открыть начало содержательного вступления](http://127.0.0.1:4349/#step=performance-question).
Общая схема сохранена отдельным слайдом, прежние объяснения возвращены. Новых экспериментов нет.

Далее — SSR-иллюстрация и исследования. В [layout-сцене](web-layout-framework.md)
`mini-layout` показывает диагностические traces, `layout-framework-check` — все шесть сравнительных пар:
медианы 88 → 64 ms, одинаковый итог, 0 missing/invalid. Это локальный browser endpoint, не полевой INP.
Отдельный [RN framework](framework-native.md) открывает мобильную часть;
подробности неубедительной RN-серии остаются в подготовке/Q&A. Основной RN-кейс ещё не встроен.

## Где обещания доклада ещё не превращены в сцены

[Зафиксированная тема и полное описание](../../../docs/research/performance-observability/CONFERENCE_BRIEF.md)
остаются обязательными. Следующие пункты — **отсутствующие сцены**, их нет среди нынешних слайдов:

| Обещание | Что есть сейчас | Что ещё нужно предъявить |
| --- | --- | --- |
| TTI | App readiness и схема границ | Объяснение legacy TTI, его отличия от выбранного readiness marker и отдельная проверка действия |
| Hydration | B измеряет клиентский startup | SSR-страница: HTML уже виден → действие ещё не работает → конкретная причина → исправление → повторное измерение |
| React DevTools → web fix | Profiler API и диагностические browser profiles | Настоящий проход в React DevTools с локализацией проблемы, изменением кода и сопоставимыми результатами |
| RN before/after и JS jank | Hermes нашёл full-history aggregation; Release interaction study не прошёл validity gate | Эквивалентная работа, воспроизводимое улучшение действия, показ приложения и диагностического профиля |
| RN startup | Release host и bootstrap | Native launch → usable endpoint, cold/warm условия и повторные измерения |
| Hermes | Реальные импортированные Debug sampling profiles | Встроить диагностический проход в основной рассказ; не выдавать Debug за Release benchmark |
| Flashlight | Сохранённого запуска нет | Поддерживаемый Android-доступ и настоящий отчёт; подтверждён только iPhone |
| Культура измерения | Playwright/Maestro и сохранение JSON | Baseline → обоснованный performance budget → намеренное замедление → падение CI → отчёт и владелец |

RN-результат нельзя улучшить редактурой: [loaded-input study](../../../docs/research/performance-observability/RN_LOADED_INPUT_RESEARCH.md)
сохранил все 27 gestures, один phase budget miss и `hypothesis: inconclusive`. Это не готовый успешный before/after.
В то же время [Hermes](../../../docs/research/performance-observability/HERMES_PROFILE_RESEARCH.md) действительно
показывает место работы; диагноз и доказанный UX-эффект — разные достижения.

## Что проверяем следующим

Сначала вместе пройти файлы 05/06: понятен ли зрителю симптом, причина и практический вывод, а не только таблица.
Затем вручную проверить одну недостающую hydration-сцену в браузере. Только если симптом воспроизводим,
фиксировать минимальный протокол и сравнение. Параллельных новых стендов этот документ не предлагает.
RN и остальные обещания остаются незакрытыми; hydration сама по себе доклад не завершит.

Сценарий не заменяет источники: [текущие тексты](../../../docs/research/performance-observability/CONFERENCE_SLIDES.md),
[порядок и старый тайминг](../../../docs/research/performance-observability/CONFERENCE_RUN_OF_SHOW.md),
[сгенерированные карточки](../graph/src/deck/deck.ts), [A/B overrides](../graph/measurement-cards.json).
Большая часть raw evidence живёт локально в соседнем `performance-observability/reports/`, игнорируется Git
и не переносится вместе с этим документом. В Git лежат два A/B кадра; они не заменяют исходные отчёты.
