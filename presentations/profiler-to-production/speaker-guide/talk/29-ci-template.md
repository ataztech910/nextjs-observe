## Текст

В начале я обещал рассказать, как не потерять такое нажатие в следующем релизе. Вот ответ. *(показать)*

Одна папка, один workflow, две проверки. Копируете папку в репозиторий, workflow кладёте в `.github/workflows` — и проверки запускаются на каждом pull request. Для React Native — та же проверка хука, только с Testing Library для React Native.

Ссылку на шаблон выложу в LinkedIn и на сайте. QR будут в конце.

Но шаблон — не главное. Главное — привычка. Вспомните последний баг производительности, который вы чинили. Найдите в нём поведение или счётчик, который должен оставаться верным. И сделайте из него проверку.

А после релиза — те же счётчики через OpenTelemetry, по версиям и длине сессии. CI ловит то, что можно воспроизвести до релиза. Наблюдение — то, что CI не воспроизвёл. Например, тридцатый визит в длинной сессии.

Честно: локально workflow проверен, на GitHub ещё не запускался.
