# 13 · Could the rest of the page delay the button?

`step: web-streaming-mechanism` · Веб: кнопка есть, кода нет · **7:50 → 8:40** (0:50)

**На экране:** дорожки: HTML приходит частями (каталог сразу, рекомендации через 3 с), обычный модуль ждёт конца разбора документа и стартует только после рекомендаций.
**Задача слайда:** развязка веб-загадки. Сложить три факта в цепочку: документ не закончен, пока нет рекомендаций → обычный модуль ждёт конца документа → кнопка ждёт рекомендаций. Сразу сказать, что это гипотеза, и что ранний старт кода ещё не доказывает работающую кнопку.

## Текст

Сервер отдаёт эту страницу по частям. Первая часть — каталог и кнопка — уходит сразу. А потом сервер держит соединение открытым: он ждёт рекомендации, чтобы дослать их в тот же документ.

Для покупателя это хорошо: товары видны сразу. Но для браузера документ всё это время не закончен.

Клиентский код подключён как обычный модуль, `script type="module"`. У такого скрипта правило: он выполняется, когда браузер дочитал документ до конца. *(показать оранжевую дорожку)*

Теперь сложим. Документ заканчивается, когда приходят рекомендации. Код ждёт конца документа. Значит, кнопка ждёт рекомендаций.

Блок, которого покупатель даже не ждал, почти три секунды держал его кнопку.

*(пауза)*

Пока это гипотеза. Если она верна, тот же модуль с атрибутом `async` — он конца документа не ждёт — должен стартовать сразу. Это мы уже видели: 36 миллисекунд. Но ранний старт кода — ещё не работающая кнопка. Нужно снова нажать и посмотреть на список.
