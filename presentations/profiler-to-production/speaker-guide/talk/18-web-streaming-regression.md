# 18 · Can the measurement catch the regression?

`step: web-streaming-regression` · Веб: кнопка есть, кода нет · **11:40 → 12:30** (0:50)

**На экране:** три пары запусков. async — 3 / 3 подтверждено за 1,2 с → PASS. Обычный module — 0 / 3 → FAIL. Счётчики через OTLP совпали.
**Задача слайда:** проверить саму проверку — сломать страницу нарочно и убедиться, что она краснеет. Закрыть веб-кейс возвратом к покупателю и его жалобе со слайда 7.

## Текст

Проверку, которая должна ловить регрессию, нельзя проверять на работающем коде. Её надо проверять на сломанном.

Поэтому мы сломали страницу сами — убрали `async` и вернули ту самую ошибку. И заранее, до запуска, записали правило: ранний клик должен получить подтверждение за 1,2 секунды. Нет подтверждения — провал.

Три пары запусков. С `async` — три подтверждения из трёх: PASS. Без `async` — ноль из трёх: FAIL.

Счётчики, которые дошли через OpenTelemetry, совпали с тем, что видел приёмник. А сама проверка вернула код выхода: ноль для рабочей версии, единицу для сломанной. Такой код понимает любой CI.

Честно: в настоящем CI мы это ещё не запускали — только локально. И 1,2 секунды — выбор для опыта, а не бюджет для вашего продукта.

Вернёмся к покупателю. Он нажимает «сначала дешёвые» — и получает список. А если в следующем релизе кто-то уберёт это слово, проверка покраснеет раньше, чем покупатель напишет в поддержку.
