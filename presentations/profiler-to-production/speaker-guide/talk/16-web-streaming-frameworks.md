# 16 · Why Next.js already does this

`step: web-streaming-frameworks` · Веб: кнопка есть, кода нет · **10:10 → 10:50** (0:40)

**На экране:** Next.js 16.3.8 production build — 7 из 7 клиентских чанков `<script async>`, восьмой — noModule-полифил. Ниже — когда проблема возвращается.
**Задача слайда:** ответить разработчику на Next.js, который думает «у нас такого нет». Он прав — фреймворк уже защищает его. Но об этой защите узнают, только когда уходят от неё, и Lighthouse этого не покажет.

## Текст

Если вы пишете на Next.js, вы сейчас, скорее всего, думаете: у нас такого нет. И вы правы.

Я собрал production-сборку Next.js 16 и открыл HTML. Семь клиентских скриптов из семи подключены с `async`. Восьмой — полифил для старых браузеров. Фреймворк уже сделал то исправление, к которому мы сейчас пришли сами.

То есть эта защита у вас есть — и вы о ней, возможно, не знали. Заметить её можно, только уйдя от неё. Свой сервер со стримингом. Свой entry с `type="module"` без `async`. Кнопка снова начнёт ждать. А Lighthouse по-прежнему покажет сто.

Поэтому, когда меняете фреймворк или настройку сборки, проверяйте действие, а не оценку.

Проверял я только Next.js 16.3.8, на одной странице. Про другие фреймворки ничего утверждать не буду.
